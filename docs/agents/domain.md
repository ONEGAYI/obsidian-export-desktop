# 领域文档读取约定

**当前按一个产品上下文阅读**：Rust CLI 与 Tauri 桌面端服务于同一套笔记导出流程。`desktop/src-tauri` 的独立 Cargo workspace 是构建边界；`desktop/pnpm-workspace.yaml` 目前只声明构建许可，均不足以要求拆成多个领域文档。

## 阅读顺序

1. 根 `AGENTS.md`：产品定位、桌面端与边车职责、工程规则。
2. `docs/sidecar-events.md`：导出、链接检查和更新的事件流契约。
3. 当前任务的 GitHub 总规格 Issue 及子任务：本次范围、设计决定和验收条件；本地 `.scratch/<feature>/handoff.md` 提供入口，`spec.md` 仅是首次发布快照。
4. 涉及历史取舍时阅读 `docs/known-limitations.zh.md`；构建与运行阅读 `docs/BUILD.md`。

以后若新增 `CONTEXT.md` 或 `docs/adr/`，进入相关工作前一并阅读。当前两者不存在，按既有文档继续工作，不为了占位创建文件。出现需要长期记录的新术语或架构决策时，再通过 domain-modeling 维护。

## 本项目的用语

- **来源**：用户指定的 vault 目录或手动输入的单篇笔记路径；当前浏览按钮选择目录。
- **导出目标**：用户输入或选择的目标路径。
- **实际输出目录**：桌面 Rust 后端按来源类型和“保留根文件夹”选项解析的落点；不是简单拼接输入字符串。
- **边车**：随桌面端启动的 obsidian-export CLI；负责实际转换。
- **配置摘要**：当前选项的只读展示，不是预设管理，也不是工具安装状态检查。

以上说明供导航与消歧；转换语义以相应源码和事件契约为准。新规格若与根规则或既有契约冲突，必须明确指出并解决，不能默默覆盖。
