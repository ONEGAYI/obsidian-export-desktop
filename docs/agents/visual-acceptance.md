# 视觉验收代测交接约定

> 触发：GUI 需要真实窗口的视觉/交互验收（布局断点、主题配色、全流程回归、键盘可达性）时读本文件。纯逻辑与纯函数行为走 vitest / cargo test，不适用本模式。

## 为什么是交接文档而非直接控窗

实现 Agent 用 computer-use 直接操控 Tauri 窗口效率极低，26.9.3 周期实测后弃用：WebView 的 AX 树不可读（元素坐标多为 0,0,0,0）、坐标点击受前台窗口限制、截图外链转写易 403、多轮观察-点击来回烧时。替代模式：

**实现 Agent 写交接文档 → 用户转交原生多模态 Agent 执行 → 报告回传 → 实现 Agent 判定处置**

多模态 Agent 有真实视觉与高效窗口控制（含自建 win-ctl.ps1 精确控尺），是这条流水线里唯一合适的执行者。

## 交接文档模板

放临时目录（如 `%TEMP%\<feature>-smoke\`），包含：

- **环境**：启动方式（`just desktop-dev` 后台跑、**不带管道**——管道会截断 stdout 使应用退出）、测试数据（vault 与输出目录的绝对路径）、界面语言与主题初始态
- **检查清单**：逐项含输入操作、期望结果、判定标准——判定标准必须是可观测的事实（「右栏出现」「像素采样 #F5F4F1」「计数显示 60000 成功」），不写「布局正确」这类不可判定表述
- **视口控制**：MoveWindow 迭代逼近目标客户区尺寸；CSS 视口 = 客户区物理像素 ÷ DPI 缩放（150% 下 ÷1.5），先以默认窗口反推换算系数再定位
- **截图约定**：逐项命名（如 `V3-999x800.png`），与清单编号对应
- **报告落点**：同目录 `<name>-report.md`，格式为总判定 + 逐项结果表 + 缺陷清单（复现步骤/期望/实际/机制线索/证据截图）+ 收尾状态（应用偏好恢复、进程退出、测试数据保留与否）
- **边界**：只测不改、零仓库修改、零 git 写操作

## 报告回传后

缺陷逐条判定：修复（能写纯函数回归的先写测试）/ 登记 issue / 观察项（注明根因与建议）。报告与关键截图归档 `.scratch/<feature>/reports/` 入库留痕（26.9.3 的三份先例：烟测、视口矩阵、全流程回归）。

## 用户侧转交提示语（直接复制）

「请读取 `<交接文档路径>` 并按其执行验收，完成后把报告写入同目录 `<报告文件名>`。只测不改，不碰 git。」
