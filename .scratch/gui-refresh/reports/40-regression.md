## 缺陷清单

### #1 【低 · 文档与实现不一致】设置页导航形态断点与交接描述不符

- **复现**：默认窗口（760×520）打开「选项」。
- **期望**（交接 A1 原文）：默认窗为横排页签（顶部可横滚），宽窗为左侧导航列。
- **实际**：760×520 显示**左侧导航列**；横排页签仅在宽 <640 CSS px 出现。
- **定位**：`desktop/src/components/OptionsView.tsx:343` —— 导航容器 `flex-row … sm:flex-col`，切换点为 Tailwind `sm:`（640px），默认窗 760 > 640 故显示左列。
- **佐证**：560×480 实测横排页签正常（可横滚、省略号、焦点环），导航与键盘行为两形态均无问题。
- **判定**：功能无缺陷；属验收文档表述与实现断点不一致，建议实现 Agent 确认预期断点后统一口径（改文档或改断点）。

### #2 【低 · 待确认】取消竞态：「导出已取消」与全量成功计数并现

- **复现**：60000 篇导出至约 50%（R1 截图定格 29889/60000）后点「取消导出」。
- **期望**：取消后汇总计数应反映中断时刻的部分进度。
- **实际**：标题正确显示「导出已取消」，但汇总行为「共 60000 篇：60000 成功 · 0 跳过 · 0 失败」；磁盘核对 `smoke-out-40\huge-vault` 产物恰为 60000 个文件。
- **分析**：取消命中在「导出实质已完成、完成事件尚未被前端处理完」的竞态窗口——边车事件缓冲已全部到达，kill 仅抢在终态事件之前，终止被归为「取消」。标题与计数语义对用户存在矛盾观感。
- **建议**：取消时冻结计数快照，或对「全量完成 + 取消」组合归一为完成态。供实现 Agent 权衡。

### #3 【观察 · 非缺陷】取消后链接检查照常自动运行

- 导出被取消后，链接检查面板仍自动启动并完成（60000 文件扫描）。导出实质完成时此举合理；若将来取消能真正中断半途导出，「已取消仍全量跑检查」的产品语义建议一并确认。

### #4 【自动化观察 · 非用户缺陷】Switch 类控件对 UIA Invoke 无响应

- 「硬换行」「导出后链接检查」等开关（radix Switch 形态）用辅助功能 AXPress（UIA Invoke）点击两次均无效，改用真实鼠标事件（event 坐标点击）后一次生效；普通 button/tab/radio/checkbox 的 AXPress 全部正常。真人操作不受影响；自动化测试需对 Switch 使用真实指针事件。

### 额外验证（计划外收获）

- **检查失效列表大样**：cancel-vault（3000 篇、6000 条死链/嵌入）触发「链接检查：6000 失效」视图——红色「目标不存在：×××」标注、Wikilink/嵌入类型标签、仅失效/全部/跳过筛选页签、「仅显示前 300 条，共 6000 条」截断提示全部正常（含窄屏与宽屏两形态）。
